# Лабораторна робота №2. Рівень 3 — мінімальний образ scratch

**Виконавець:** Салига Богдана

## Мета

Зібрати мінімально можливий образ виконання, використавши `scratch`
замість базової ОС.

## Три розміри образів

| Образ | Опис | Розмір (байти) | Приблизно |
|---|---|---|---|
| `vtfk-naive` | Одноетапна наївна збірка (1× FROM) | 2 342 012 123 | ~2.34 GB |
| `vtfk-slim` | Багатоетапна збірка на `debian:12-slim` | 114 207 385 | ~114 MB |
| `vtfk-scratch` | Багатоетапна збірка на `scratch` (musl static) | 801 717 | ~800 KB |

**Співвідношення:**
- `vtfk-scratch` / `vtfk-naive` = **0.034%** (у ~2900 разів менший).
- `vtfk-scratch` / `vtfk-slim` = **0.7%** (у ~142 рази менший).

## Порівняння шарів — docker history

### vtfk-slim

Найбільший шар — **базовий `debian:12-slim` (85.3 МБ)**.
Сам бінарник — лише 463 кБ.

### vtfk-scratch

Усього **два шари**: метадані (0B) і **сам статичний бінарник** (553 кБ).
Жодної ОС, жодних бібліотек.

## Як досягнуто scratch

1. **Статичне лінкування через musl.** У `Dockerfile.scratch` додано таргет
   `x86_64-unknown-linux-musl` і компіляція через `cargo build --release --target x86_64-unknown-linux-musl`.
   Усі бібліотеки вбудовуються всередину бінарника — він не залежить від `/lib/ld-linux.so`.

2. **Багатоетапна збірка.** Образ `rust:1.99` використовується як тимчасовий
   етап `build`, а у фінальний `scratch` копіюється лише один файл — готовий бінарник.

3. **Кешування шарів залежностей.** `Cargo.toml` і `Cargo.lock` копіюються
   окремим шаром **до** копіювання `src/`. При зміні лише коду шар компіляції
   залежностей береться з кешу (`CACHED`).

## Висновок

Фінальний образ на `scratch` містить **лише статично злінкований бінарник** —
жодної ОС, жодних бібліотек. Це дає розмір **801 717 байт (≈800 КБ)** проти
**2.34 ГБ** у наївного та **114 МБ** у `debian:12-slim`. Образ запускається
без помилок динамічного лінкера: `docker run --rm vtfk-scratch` друкує
`vtfk-sid lab03: hello from scratch` і завершується з кодом 0.
